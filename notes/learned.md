# What I learned

The agent adds two short sentences after each step.

- Step 1: We wrote down your job (teacher and researcher), your weekly files and your AI level (2). Worth remembering: the agent only needs made-up data, so you never have to share real student or research data.
- Step 4: We wrote a plan for the Call Tracker in `projects/call-tracker/PLAN.md`. Worth remembering: the OUT list matters as much as the IN list, because it keeps the first version small.
- Step 5: We built the first Call Tracker page in `projects/call-tracker/index.html`, with 12 made-up calls. Worth remembering: deadlines are counted from today, so the sample stays useful on any day.
- Step 6: We checked the page against the three "done when" points by opening it in a hidden browser, and all three passed. Worth remembering: "checked" means we saw the result, not that we expect it to work.
- Step 7: We wrote `projects/call-tracker/MONDAY.md`, a plan for gathering real calls automatically every Monday. Worth remembering: start by hand with one source, then automate it.
- Step 7 (second round): The page can now load calls from a `calls.csv` file and remembers them, and we tested good, bad and wrong files. Worth remembering: a clear error message for a bad row saves time once real data arrives on Monday.
- Step 7 (third round): The page now also reads CSV files from European Excel (";" separator, dates like 15.1.2027), and we tested it. Worth remembering: test with a file shaped exactly like the one you will really use.
- EU search: We wrote `fetch_eu_calls.py`, which collects real EU calls for your keywords into `eu_calls.csv` for the page. Worth remembering: don't trust a "status" label blindly; we checked the deadlines and found it was wrong.
- More keywords: We added six keywords; only "multilingual" and "benchmarking" found extra EU calls. Worth remembering: exact phrases are precise but narrow, so a keyword can also match an off-topic call (e.g. "environmental benchmarking").
- Dashboard: We added a "not my topics" list to the EU script, plus a summary with four numbers and two charts (deadlines per month, calls per keyword). Worth remembering: a screenshot found a layout problem and a wrong sentence that our click tests had missed.
- Second source and keyword editor: `fetch_calls.py` now reads the EU portal and HRZZ together, and you can add, edit and delete keywords on the page, saved in `keywords.js`. Worth remembering: one shared settings file means the page and the script can never disagree about your keywords.
- Refresh button: A small local helper (`serve.py`) lets the page start the search in the background and update itself, and the page opens the newest results without a Load click. Worth remembering: a web page can't start programs by itself, so a helper that only listens on your own laptop bridges the gap safely.
- Three more sources: eufondovi, AMPEU and UNIZG now feed the tracker (31 calls, 13 open). Worth remembering: every new source needs a filter for what is NOT a call (results, notices, job ads), and a spot check against the real website.
- Plan updated: `PLAN.md` now describes the tool as it really is (5 sources, dashboard, keyword editor, Refresh). Worth remembering: a plan is only useful while it matches the tool, so update it after big changes.
- Test suite: `python3 run_tests.py` now checks 49 click paths and script parts, and it found 5 real bugs that are now fixed. Worth remembering: write the test for a bug first, see it fail, then fix it, so you know the fix really works.
- More calls: the tracker now browses all ~520 open EU calls, ranks them with a fit score and hides the weak ones behind a switch, and adds Devpost hackathons. Worth remembering: more data needs a way to rank and hide it, otherwise the best matches get buried; and a test that checks "no duplicates" can reveal how the real data is shaped.
- Search, dismiss, NEW: the page now has a search box, a Dismiss button and a NEW badge, all saved in your browser. Worth remembering: a test that failed because of my own test data ("a" matches everything) taught me to check the test before blaming the tool.
- Hand-kept list and Share: events without a data feed now come from `my_calls.csv` (only dates I read from the event's own page), and every call can be shared as an e-mail draft, a copy or the system share sheet. Worth remembering: when a source gives no date, don't invent one; leave it on a watch list and say so.
- Card colours: each kind of data on a card now has its own soft colour. Worth remembering: colour helps scanning, but keep the words on every label and test the contrast, so the page stays readable for everyone.
- Weekly refresh and card layout: `weekly_refresh.py` runs the search, keeps a log and writes a "what is new" summary; scheduling stays a step I do myself because it lives outside this folder. Worth remembering: ask the screenshot, not only the code: it showed the buttons floating mid-card and wrapping into two lines.
- Select and share: cards now have checkboxes and a bar to share exactly the selected ones. Worth remembering: a test that only trusts a label ("hidden") can pass while the screen shows something else, so check what is really visible; it found a bug in two switches that had been showing for a while.
- Rule-based on purpose: we decided the tool uses no AI model, only feeds, scraping and fixed rules. Worth remembering: that makes it free and predictable and lets tests check exact results; the price is that it only understands titles and patterns, not meaning.
- Checking CLARIN, EOSC, COST: only COST gave a usable signal (a "closed" notice), EOSC refused automated readers and CLARIN had no open call. Worth remembering: when a site says no, accept it; and when there is nothing to list today, a small watch that flags the change can still be useful.
- Sources panel, notes, calendar file, EU details: the page now says which sources work, you can write notes and download deadlines for your calendar, and EU calls show amount, opening date and description. Worth remembering: my test copied my own typo and passed while the code was wrong; always read the real output once, not just the green result.
- Outside my field everywhere: every source now keeps off-topic calls behind one switch instead of dropping them silently, and the fit score knows Croatian words. Worth remembering: a hidden rule you cannot inspect is a risk; make the tool show what it left out, and keep only the real noise (job ads, results) out for good.
- Icon and favicon: the site has its own icon (a calendar with a highlighted deadline day), drawn by `make_icons.py` in all sizes. Worth remembering: an icon has to work at 16 pixels, so keep the shapes big and simple, and look at it small and on dark backgrounds, not only large.
- Where filter: hackathons can be filtered online / in person, with the venue on the card. Worth remembering: look at the real data before designing a filter: 56 of 62 events were online and the rest gave only a venue name, so a "Europe" filter would have been guesswork.
